# 누군가 널 위해 기도하네

여러 사람이 기도제목을 나누고, 성경 통독을 함께 체크하는 웹앱이에요.

- 이메일 + 비밀번호 로그인, 언제든 바꿀 수 있는 별명
- **서버**
  - 회원가입할 때 입장 코드를 넣으면 그 서버로 들어가요. 로그인할 때는 코드가 필요 없어요.
  - 멤버와 서버 관리자에게는 서버 목록이나 다른 서버가 보이지 않아요. 서버에서도 목록을 보내지 않아요.
  - 서버를 바꾸는 메뉴와 「내 서버」 설정은 총 관리자에게만 있어요.
  - 기도제목, 응답 보관함, 함께 읽는 사람들은 서버마다 따로 보여요.
  - 성경 읽기 기록은 개인 기록이라 모든 서버에 같이 반영돼요.
- **관리자**
  - **총 관리자**: 서버 만들기·이름 바꾸기·삭제, 서버 관리자 임명·해제, 모든 서버 보기와 관리
  - **서버 관리자**: 자기 서버의 부적절한 기도제목 삭제, 멤버 내보내기, 새 입장 코드 만들기
- 기도제목 나누기: 별명 또는 익명, 기간 선택 (기본 1주)
- 「기도했어요」 체크: 사람마다 따로, 기도제목마다 1시간에 한 번. 함께 기도한 전체 횟수가 보여요.
- 응답 기록: O / X / Wait / His Way / 선택 안 함 + 코멘트
- 응답 보관함: 공개 또는 나만 보기
- 성경 통독
  - 기간·범위(구약/신약/신구약)·횟수 목표 설정 (기본: 그해 1월 1일 ~ 12월 31일 신구약 1회)
  - 장 단위 체크 (누른 채로 밀어서 여러 장을 한 번에 선택)
  - 잘못 누른 기록은 「잘못 누른 기록 지우기」로 지울 수 있어요.
  - 진행률과 하루에 읽어야 할 장 수 (소수점 한 자리)
  - 최근 7일 그래프, 같은 서버의 별명별 진행률
  - 오늘 읽은 사람 수 (누가 읽었는지는 보이지 않아요)
- 하루 기준: 한국 시간 **새벽 3시**에 날짜가 바뀌어요.
- 라이트모드(해 뜬 동산) / 다크모드(밤의 동산), 바꿀 때 부드럽게 전환
- 글자 크기 4단계 (내 정보 → 화면과 글자 크기). 손가락으로 확대되지 않게 막아 두었어요.
- 성경 한 권을 다 읽으면 폭죽으로 축하해요.
- 문의하기: 누구나 개발자에게 의견을 보낼 수 있어요(답장 없이 한 방향). 총 관리자는 「내 정보 → 받은 문의」에서 모아 봐요.

## 파일

| 파일 | 설명 |
|---|---|
| `index.html` | 앱 전체 (GitHub Pages에 올리는 파일) |
| `logo-light.png`, `logo-dark.png` | 라이트·다크모드 로고 |
| `supabase.sql` | 데이터베이스 설정 스크립트 |

`index.html`의 Supabase 설정이 비어 있으면 **체험 모드**로 열려요. 체험 모드의 기록은 그 브라우저에만 저장돼요.

## 설치 순서

### 1. Supabase 프로젝트 만들기
1. supabase.com 에서 새 프로젝트를 만들어요. 지역은 Seoul(Northeast Asia)을 추천해요.
2. 왼쪽 메뉴 **SQL Editor**를 열어요.
3. `supabase.sql` 내용을 전부 붙여넣고 **Run**을 눌러요. 다시 실행해도 괜찮아요.

### 2. 앱에 서버 주소 넣기
1. Supabase **Project Settings → API**에서 두 값을 복사해요.
   - **Project URL**
   - **anon public key**
2. `index.html`에서 아래 두 줄을 찾아 따옴표 안에 붙여넣어요.
   ```js
   const SUPABASE_URL = 'https://xxxx.supabase.co';
   const SUPABASE_ANON_KEY = 'eyJ...';
   ```
3. 키에 대해 알아둘 점
   - anon key는 웹페이지에 공개돼도 괜찮아요. 데이터는 보안 규칙(RLS)으로 보호돼요.
   - **service_role key는 절대 넣지 마세요.**

### 3. GitHub Pages에 올리기
1. GitHub 저장소에 `index.html`, `logo-light.png`, `logo-dark.png`를 올려요.
2. **Settings → Pages**에서 main 브랜치로 배포해요.

### 4. 가입 확인 메일 설정
1. Supabase **Authentication → URL Configuration**에서 **Site URL**을 GitHub Pages 주소로 바꿔요. 가입 확인 메일의 링크가 이 주소로 돌아와요.
2. **Authentication → Sign In / Providers → Email**에서 「Confirm email」을 켜요.
3. Supabase 기본 메일 서버는 프로젝트 팀원 주소로만 메일을 보내요. 다른 사람이 가입하려면 **직접 SMTP를 연결**해야 해요.
   - Gmail로 보내기: Google 계정에서 2단계 인증을 켜고 「앱 비밀번호」를 만든 뒤, Supabase **Authentication → Emails → SMTP Settings**에 넣어요.
     - Host `smtp.gmail.com`, Port `587`
     - Username은 내 Gmail 주소, Password는 앱 비밀번호
   - SMTP를 연결하면 **Authentication → Rate Limits**에서 시간당 메일 수를 늘릴 수 있어요.

### 5. 총 관리자 지정
1. 앱에서 총 관리자가 될 이메일로 가입하고 별명을 정해요.
2. Supabase **SQL Editor**에서 아래 한 줄을 실행해요.
   ```sql
   select public.make_super_admin('joseungchan164@gmail.com');
   ```
3. 앱을 새로고침하면 「내 정보 → 서버 관리」가 생겨요.
   - 여기서 서버를 만들면 입장 코드가 나와요. 그 코드를 함께할 사람들에게 알려주세요.
   - 서버를 누르면 멤버 목록에서 「관리자로 임명」을 할 수 있어요.

이 함수는 SQL Editor에서만 실행돼요. 앱 사용자는 스스로 관리자가 될 수 없어요.

### 6. 휴대폰에서 쓰기
Safari나 Chrome으로 주소를 열고 「홈 화면에 추가」를 누르면 앱처럼 쓸 수 있어요.

## 동작 규칙 (서버에서 지켜져요)

- **서버 멤버만**: 그 서버의 기도제목을 보고, 쓰고, 체크할 수 있어요. 내보내진 사람은 바로 볼 수 없게 돼요. 입장 코드를 알면 다시 들어올 수 있으니 필요하면 「새 코드」를 만들어 주세요.
- **관리자 권한**: 서버 관리자는 다른 관리자를 내보내거나 임명할 수 없어요. 그건 총 관리자만 할 수 있어요.
- **오늘 읽은 사람 수**: 서버는 숫자만 보내고, 누가 읽었는지는 보내지 않아요.

- **익명 기도제목**: 다른 사람에게 작성자가 전혀 전달되지 않아요.
- **기도 체크**: 같은 기도제목은 1시간에 한 번만 할 수 있어요. 기간이 끝났거나 응답이 기록된 기도제목은 체크할 수 없어요.
- **목록에서 사라지는 경우**
  - 응답(O/X/Wait/His Way/선택 안 함)을 기록하면 진행 중 목록에서 빠져요.
  - O/X/Wait/His Way 중 「공개」인 것만 모두의 응답 보관함에 보여요.
- **읽은 날짜**: 서버 시간 기준(새벽 3시에 바뀜)으로 기록돼서 기기 시계와 상관없어요.
- **통독 진행률**: 목표 기간 안에 읽은 장만 셉니다. 여러 회 통독이면 같은 장을 그 횟수만큼 읽어야 해요.
- **별명**: 다른 사람과 겹칠 수 없어요.
